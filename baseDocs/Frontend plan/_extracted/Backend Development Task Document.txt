Backend Development Task Document
Express.js API + Supabase Auth, PostgreSQL, Storage, and Realtime
1. Backend Scope
The backend will be built using Express.js and will act as the control layer between the Next.js frontend and Supabase.
Architecture:
Next.js Frontend → Express.js API → Supabase
The backend is responsible for:
Authentication relay to Supabase Auth
Role-based access control
Product CRUD
Category CRUD
Cart management
Guest cart merge
Checkout and order creation
Order status management
Admin SMS alerts
Product image upload to Supabase Storage
Product image cleanup from bucket
Customer notifications
Admin settings
Soft delete rules
Customer cancellation rules
The frontend should not directly perform privileged Supabase actions.

4. Middleware Tasks
4.1 Auth Middleware
Tasks:
Read access token/session from request.
Verify with Supabase Auth.
Fetch matching app user from users table.
Attach user to request object.
Expected result:
req.user = {  id,  supabaseUserId,  role,  phone,  email}
4.2 Admin Middleware
Tasks:
Check if req.user.role === "admin".
Reject non-admin users.
Return 403 for forbidden requests.
4.3 Age Gate Middleware
Tasks:
Check age-gate session/cookie.
Block access if missing.
Hard block users who answered “No.”
Apply to required routes if backend serves protected public content.
4.4 Validation Middleware
Tasks:
Validate request body.
Validate query params.
Validate route params.
Return 400 for invalid input.
Use for:
Product creation
Category creation
Cart item update
Checkout
Settings update
SMS test
Image upload

6. Backend Business Logic Tasks
6.1 Product Business Rules
Tasks:
Public products must only show if visible and not deleted.
Admin can see hidden products.
Admin can restore soft-deleted products.
Price must be dynamic.
Measurement unit must be dynamic.
Product must belong to category.
Product can have maximum 3 images.
6.2 Image Business Rules
Tasks:
Validate image type.
Validate image size.
Reject more than 3 images.
Upload to Supabase Storage.
Save returned URL/path in product record.
First image becomes cover.
Allow cover image change.
Delete old bucket file when image is replaced.
Delete bucket file when image is removed.
6.3 Cart Business Rules
Tasks:
Guest cart is handled on frontend.
Customer cart is stored on backend.
Merge guest cart after login.
Validate products during merge.
Ignore deleted or hidden products.
Use current product price during checkout.
Prevent invalid quantity.
6.4 Order Business Rules
Tasks:
Order requires authenticated customer.
Order must be created from valid cart.
Order status starts as Pending.
Payment method is COD.
Product snapshot must be stored.
Delivery address snapshot must be stored.
Cart must be cleared after order.
Admin SMS must be sent after order creation.
SMS failure should be logged but should not cancel successful order.
6.5 Notification Business Rules
Tasks:
Create notification when admin changes order status.
Store notification in database.
Customer can read own notifications only.
Use Supabase Realtime for live update.
No SMS to customers for order status changes.
6.6 Customer Cancellation Business Rules
Tasks:
Check admin setting before allowing cancellation.
Allow customer cancellation only for own order.
Allow cancellation only for Pending status unless changed later.
Hide frontend button, but also enforce in backend.
